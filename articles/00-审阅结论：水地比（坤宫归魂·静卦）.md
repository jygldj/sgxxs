### 三、**暴露一处真代码 bug（关键发现）**

**`suanfa.js:996-1014` 的 R1-4 反吟伏吟判定**：

```
// R1-4 反吟伏吟：本卦与变卦六爻地支逐一相冲→反吟，逐一相同→伏吟
function suanFanYinFuYin(guaInfo) {
    ...
    for (let i = 0; i < 6; i++) {
        const d1 = yaoDetail[i].dizhi, d2 = bianYao[i].地支;
        ...
        if (d1 !== d2) sameAll = false;
    }
    ...
    if (sameAll) guaInfo.guaXiang.fuYin = true;  //  ← 这里误判
}
```

**问题**：把「本卦==变卦」(**无动爻的静卦**) 误判为「伏吟」。

因为：静卦无动爻 → 变卦就是本卦本身 → 地支逐一相同 → `fuYin=true`，**但伏吟的真义是"动爻翻转后变卦仍与本卦重合"**（纯卦动一爻仍为纯卦），静卦根本不存在"动变"过程，**不应被标 fuYin**。

**实测本卦被标**：`guaXiang.fuYin = true`（误）+ `guaXiang.duFa = '六爻安静'`（对）→ **自相矛盾**。

**衍生后果**：

1. `suanfa.js:1449` 计分："卦伏吟，事主呻吟迟滞，进退两难" → 误扣 1 分（实为静卦无事）
2. `jiegua.html:1041` 前端渲染"伏吟"标签（橙色徽章）
3. AI 收到 `gxTags.push('伏吟')` 后（qwen.js:84）即被误导写出"全卦皆静，呈伏吟之态"

### 四、**LLM 层概念错用（与代码 bug 互为因果）**

`qwen.js:145` 已设警告："⚠ 静卦（六爻无动）≠伏吟：伏吟须世爻与应爻相冲或世爻自刑方成，不可将无动爻静卦误称伏吟。"

但千问 AI 仍写出"全卦六爻皆静，呈伏吟之态"——**LLM 提示遵循性不足**，与算法层误标 `fuYin=true` 形成因果链：**错标签 → 错引导 → 错释文**。

若 R1-4 修了，前端不再传 `fuYin=true`，AI 不受错误标签诱导，释文就可能正确（但 LLM 警告仍建议加固）。
